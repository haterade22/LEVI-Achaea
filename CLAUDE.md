# LEVI-Achaea Combat System - AI Assistant Guide

## Project Overview

This repository contains the **"For Levi" Mudlet package**, a comprehensive combat and automation system for Achaea (an Iron Realms Entertainment MUD). The system is built in Lua for the Mudlet client and handles complex combat mechanics including affliction tracking, intelligent curing, combat offense, and defensive automation.

**Current Systems**:
- **Mudlet Mapper (mmp)** - Advanced pathfinding and navigation
- **Ataxia Combat System** - Affliction tracking, defense management, combat automation
- **ataxiaNDB** - Player database with API integration
- **ataxiagui** - Custom GUI with Geyser

**Reference System**: Orion (community combat system)

## Documentation-First Knowledge Base (MANDATORY)

**Goal: build a world-class, code-accurate knowledge base on Achaea and everything in it.** The docs are a first-class deliverable, not an afterthought — they must stay in lock-step with the code.

**The game reference lives in `kb/` (since 2026-10-10).** Start at `kb/INDEX.md`. **How a fight works, from all logs, with the refuted claims marked: `kb/mechanics/foundations.md`.** **Afflictions and cures are the core** (`kb/afflictions/README.md`): every fight is giving afflictions and curing them, so read `kb/afflictions/` before writing offense, curing or tracking code. Raw game text (HELP, AB, WHATCURES, announcements, logs) is kept verbatim in `kb/raw/` as evidence. The user pastes new material into `C:\Users\mikew\OneDrive\Desktop\Achaea Knowledge Base.txt`, and **`/kb-ingest`** files it, cross-checks it against the code and logs disagreements in `kb/CONFLICTS.md`. `kb/afflictions/catalog.md` is GENERATED by `tools/kb_catalog.py` (game cure table joined to `curingTable` and both SSC priority tables), so re-run that instead of editing it. **`kb/classes/<class>.md` + `abilities.json`** hold every ability of every class's skills (60 skills, 1,929 abilities: syntax, cost, cooldown, target, afflictions named), generated from the Achaea wiki by `tools/kb_wiki_skills.py` (WIKI confidence: in-game `AB` wins); read a class's page before writing or changing its offense or basher code. **`kb/afflictions/afflictions.json` / `database.md`** is the game's own `AFFLICTION SHOW` record of every affliction (cures, durations, the lines you see when afflicted and cured, flags like NoRandomCure), generated by `tools/kb_affliction_db.py`; use it before guessing an affliction's behaviour or message.

**Capture tools.** `kbcapture` (asks the game and records the raw answers), `fightlog` (records our PvP fights) and their importers `tools/kb_capture_import.py` and `tools/fightlog_import.py` are described in `kb/README.md` ("Capture tools"). Run `python tools/fightlog_import.py` before you analyse one of the maintainer's fights.

**On completing ANY task** (a feature, a fix, a research finding, a confirmed game mechanic), before considering it done, put each fact you learned in its ONE home, and correct every document that states the old fact. Other documents point to the home; they do not copy it (`docs/adrs/002-knowledge-delivery-tiers.md`, the maintainer's decision of 2026-11-13).

| What you learned or changed | Its one home |
|---|---|
| Something a machine can check | A gate in `tools/` with a row in `tools/ci_steps.json`, and one line of prose that names the gate |
| A rule that every task needs | This file. It has a byte budget (`tools/check_context_budget.py`), so a rule goes in as one or two lines |
| A game fact: a cure, a blocker, a fire line, an ability, a timing | Its `kb/` page, with source and confidence tag. New raw game text goes into `kb/raw/`, unedited |
| How one class is played or fought: kill routes, ability lists, cast syntax, rotations | `.claude/classes/<class>.md`. If a section is a stub or is now wrong, rewrite it |
| How one of our systems works: architecture, state, commands, design reasons | `.claude/projects/<system>/` (a new system gets a folder with a `README.md`). **Never a section of this file** |
| A lesson or pitfall, with its incident | One titled entry in `.claude/AGENTS.md`. If a machine can check it, write the gate and name it in the entry |
| What a release changed, and why | `CHANGELOG.md` only: newest first, heading `## YYYY-MM-DD - vX.Y.Z: <title>` (CI checks the heading), then what changed, why, and how. Version history does not go into this file or into a system doc |
| The maintainer's own rules and preferences; the state of this machine | Memory (`memory/<topic>.md` + the `MEMORY.md` index), which is outside git. A fact about the code or the game never lives only there |

**Before you call a task done:** (1) each new fact is in its home; (2) `git grep` the old claim and correct each document that still states it (a fix can leave a doc calling the old behaviour current); (3) code that ships has its `CHANGELOG.md` entry; (4) plan files you worked from (`docs/plans/`) say what is done; (5) `README.md` / `GETTING_STARTED.md` are correct if setup or usage changed.

**Rules of the knowledge base:**
1. **Code-accurate over aspirational** — document what the code actually does *now*, with `file:line` anchors. If you can't verify it against the code or a game log, mark it as unconfirmed.
2. **Capture the "why"** — game mechanics learned from AB/logs, and the reasoning behind non-obvious code, are the highest-value entries. A future reader must not have to re-derive them.
3. **No orphaned knowledge** — if you learned something this session (a fire-line, a cooldown, a boon effect, a crash class), it goes into the right doc before the task is closed.
4. **Prune what's wrong** — delete or correct stale/incorrect docs rather than leaving them to mislead.
5. **A timing names its source and applies our artefacts (2026-11-13).** Every AB or wiki cost is a BASE cost. A timing,
   duration, count or damage figure says whose it is: BASE, ANOTHER PLAYER (name the logger; their artefacts are not
   known) or OURS (our logs). Our equilibrium is base x `ataxia_eqFactor` (the Aldar Diadem x0.85, worn at all times;
   Rain about x0.85 more). The factors and our readings: `kb/mechanics/balance-and-queueing.md`, "Our speed factors".
   A player's report found Mystor's 0.85 table cited as ours, with the cause "unknown".

Treat "the tests pass and it builds" as *necessary but not sufficient*. A task is complete only when the knowledge base reflects it.

## Evidence Before Claims (MANDATORY)

- **Run the proving command in this turn and quote its result row.** A result from memory, from an earlier turn or from another agent's summary is a claim, not evidence. "Tests pass" needs the row `Passed: N  Failed: 0` or `Ready to push: YES` from a run you just made.
- **A finding is a hypothesis.** What a subagent, a workflow, Codex or a reviewer reports is read at its named source before any fix. Reviewers have been wrong here in both directions.
- **A verifier that returns nothing is UNVERIFIED, never REFUTED.** A dead or empty verifier says nothing about the claim.
- **A negative search names its scope.** "No match in `src_new/triggers`", not "it does not exist".
- **Say what was not covered:** the live game, Linux paths, the CI run on `main`, a file you did not open.
- **Lessons are grep-first.** Before a change in an area, grep the headings of `.claude/AGENTS.md` (and of the memory file `bug-patterns.md`) for that area. Do not read them whole, and do not skip them.

## Build, Test and Release (MANDATORY)

```bash
/c/Python314/python -B tools/ci_local.py            # every step of CI's validate job. Push only on "Ready to push: YES"
/c/Python314/python -B tools/ci_local.py --quick    # the fast steps, while you work
/c/Python314/python tools/run_lua_tests.py [file]   # the Lua suite, or one test file (Lua 5.1 through lupa)
./build.sh                                          # src_new -> muddler_project -> Levi_Ataxia.mpackage; one build at a time
```

- **`src_new/` is the source of truth**: Lua files with a `--[[mudlet` YAML header, named `NNN_Name.lua`; group trees and inline scripts in `_groups.yaml`. `muddler_project/src/` and `muddler_project/build/` are generated. Never edit them.
- **Mudlet runs Lua 5.1.** This machine has no `lua5.1`; the `lua` and `luac` on PATH are 5.4 and give false results; the `python3` on PATH has no `lupa`. Use `/c/Python314/python`. A step that cannot run says NOT RUN and is never a pass.
- **Never edit** `tools/sim/forward.lua` (its bytes feed a hash, and the regeneration takes about 12 minutes), `tools/sim/gates_whole.json` (frozen; a change needs the maintainer's written word), or anything under `kb/raw/` (evidence). A generated `kb/` page changes only through its generator.
- **The version lives in 3 places that must match:** `version.txt`, `muddler_project/mfile`, and `ataxiaVersion` in `src_new/scripts/_groups.yaml`. Use `/version-bump`. Every change to shipped Lua is a version, with the heading `## YYYY-MM-DD - vX.Y.Z: <title>` in `CHANGELOG.md` (CI checks it). Docs, `kb/` and `tools/` changes have no version.
- **When asked to rebuild the package, do the full release flow** (bump, build, commit, push, tag). A local build alone does not reach the players: the updater installs the GitHub release.

**The release order.** Each step has failed at least once; the incidents are in `docs/ai-includes/git-and-release.md`.

1. Work in your own sibling worktree (`lv-<name>`) on your own branch. Never switch the branch of a tree that another session can be using. **Stage by path; never `git add -A` or `git commit -a`.** `ListAgents` shows the other sessions.
2. `git fetch --tags`. If origin has a tag above `version.txt`, rebase before you bump. Check again before the bump, before the push and before the tag: another session can take your number.
3. Run the full `tools/ci_local.py`. Push only on `Ready to push: YES`. `NOT YET` means files are not committed.
4. `git fetch origin && git rebase origin/main`; run the check again if the rebase brought changes.
5. `git push origin HEAD:main`. No pull request (the maintainer, 2026-11-11). `main` has no branch protection.
6. Watch the `Build & Validate` run for that commit, selected by workflow name (a push also starts "Dementia Mapper").
7. Only after that run passes: tag that commit and `git push origin vX.Y.Z`. **Push the ONE tag by name. NEVER `git push --tags`**: each stale local tag builds an old release, and the newest build becomes "Latest".
8. Refresh `muddler_project/build/` in the main checkout from the release asset (the maintainer imports the package from that folder), then remove the worktree and delete the branch.

Write a release as ONE `&&` chain with the commit message in a file: a command on the line after a heredoc runs even when the chain failed. `.githooks/pre-push` refuses two `v*` tags in one push, a tag that is not `v` + `version.txt`, a tag whose commit is not on `origin/main`, and a rewrite of `main`. The build system, the converter and the IDE tasks: `docs/reference/repository-and-build.md`.

## Model & Effort Selection (MANDATORY)

**Goal: each task runs on the cheapest model and the lowest reasoning effort that will still do it well.** Defaulting to Opus at high effort for everything is the waste this rule exists to stop.

**Main session = orchestrator.** The main session plans, decides and reviews. It hands execution to subagents and picks a model and effort for each one based on the task. It does not do bulk or mechanical work itself (sweeping searches, mass reads, running builds and tests, boilerplate edits).

### Routing guide

| Tier | Model / effort | Spawn | Use for |
|------|----------------|-------|---------|
| 1 | Haiku / `low` | `Explore` (read-only) or `general-purpose`, with `model: "haiku"` | File/code search, grepping, listing, reading and summarizing files, simple renames, formatting, boilerplate, running tests or builds and reporting results, small edits that are already well specified |
| 2 | Sonnet / `medium` | `general-purpose` with `model: "sonnet"` | Most everyday coding: implementing features from a clear plan, writing tests, normal bug fixes, refactors inside one module, docs, code review of small diffs |
| 3 | Opus / `high` | `Plan` (read-only) or `general-purpose`, with `model: "opus"` | Architecture and design decisions, ambiguous or cross-cutting changes, hard debugging where the cause is unknown, security-sensitive code, data migrations, anything expensive to get wrong or hard to undo |
| 4 | Fable | as tier 3, with `model: "fable"` | Only the hardest reasoning problems, or when Opus has already failed. Don't use it routinely |

**The custom agents are not offered today.** The six definitions in `.claude/agents/` (`fast-reader`, `implementer`, `architect`, `build-and-version`, `offense-system`, `team-class-offense`) load only when a session starts inside this repository, and sessions start in the parent folder (`docs/reference/harness-facts.md`). So spawn a built-in agent and set the model for that call, as the table says. `Explore` and `Plan` receive no `CLAUDE.md`: put the rules the agent needs in its prompt.

**Project defaults:** combat-mechanics reasoning is tier 3 unless it is clearly mechanical. That covers lock strategy, V3 affliction tracking, SSC curingset writes, and anything in the shared `ataxia/` core. Lessons Learned is mostly a list of cheap-looking changes that weren't.

### How model and effort are set

- **Per call, which is the mechanism that works today:** the Agent tool's `model` parameter (`haiku | sonnet | opus | fable`). The tool also takes an `effort` parameter, which may only be used when instructions explicitly ask. This section is that explicit permission: set effort per call when the task needs a level other than the default.
- **Agent definition** (`.claude/agents/*.md` frontmatter), for a session that starts inside the repository:
  ```yaml
  ---
  name: fast-reader
  description: ...
  model: haiku      # haiku | sonnet | opus | fable | inherit | full model id
  effort: low       # low | medium | high | xhigh | max
  ---
  ```
- **Model precedence:** per-call `model` > frontmatter `model` > `CLAUDE_CODE_SUBAGENT_MODEL` env var > the main session's model.
- `xhigh`/`max` only matter on Opus and Fable. Use them only after `high` has visibly fallen short.

### Escalation and de-escalation

- **Start at the lowest tier that plausibly fits.**
- **If a subagent's output is wrong, incomplete, or shows confusion, retry ONCE at the next tier up.** Never retry at the same tier: a second identical attempt mostly buys the same answer. An agent replying `ESCALATE: <why>` counts as a failure at its tier.
- **De-escalate:** when an Opus task breaks into well-defined steps, hand those steps down to Sonnet or Haiku. A plan tags each step with the tier that should run it.

### Transparency

Before each delegation, write one line naming the model, the effort and the reason, so the choices can be audited:

    → Haiku/low: repo-wide search for ataxiaBasher_rageAfford call sites
    → Sonnet/medium: implement step 2 of the approved plan (Psion keeper hold)
    → Opus/high: diagnose the escape-ladder livelock, cause unknown

## Code Conventions

- **Public functions** are `snake_case` with the prefix of their namespace: `ataxia_`, `ataxiaBasher_`, `ataxiaNDB_`, `ataxiagui_`; the mapper is `mmp.*`. **Module tables** are camelCase (`ataxia`, `ataxiaBasher`, `ataxiaNDB`, `ataxiaTables`). **Helpers inside a module** are `local`. Legacy names are migrated only when a file is changed much.
- **Files** are `NNN_Descriptive_Name.lua` (the number is the load order); **folders** are `snake_case`.
- **Initialise with `X = X or {}`**, and give anything a prompt path reads its full shape at load time (a reload must not crash the live path).
- **Echo to the player with the global `ataxiaEcho(...)`.** `ataxia.echo` and `ataxia.decho` do not exist; 17 call sites were once written against them and died silently. Guard an optional helper or use a real one.
- **Pure ASCII in anything that becomes an echo string.**
- **Game time is `getEpoch()`**, never `os.clock()` (that is CPU time).
- Namespace, event and test patterns with examples: `docs/reference/development-notes.md`.

## Trap Sheet

One line for each invariant. The full text, with the incident, is the entry of that title in `.claude/AGENTS.md`: grep the quoted words before you work in that area.

| Trap | Rule | Grep in `.claude/AGENTS.md` |
|---|---|---|
| The game line is the authority | A line from the game outranks our bookkeeping. Keep the derived value as a backstop; do not let it overrule the line | "outranks our bookkeeping" |
| Three separate facts | A confirmation, a lapse and a refusal each get their own handler. Stamp state on the confirmation line, never at send time | "Stamp on the confirmation line" |
| `queue addclearfull` | It wipes the whole queue. A queued command that is not an attack needs one line and a bounded hold of the dispatcher | "must hold the dispatcher", "HOLD and a REPLAY" |
| A `;` chain | Mudlet splits `;` before it sends: only the first command is queued | "chain is NOT one queue entry" |
| Saved and session state | `ataxia` and `ataxiaBasher` are saved to disk. Session beliefs, timer ids and GUI objects go on `ataxiaTemp` (`docs/adrs/001-no-gui-objects-in-saved-state.md`) | "ataxiaTemp" |
| Reload | A global that only login sets crashes the always-live path after a reload | "login-only globals" |
| A changed default | It reaches new installs only. Existing saves need a one-shot migration | "one-shot migration" |
| Trigger patterns | A pattern must fit one server-wrapped row (119 to 124 columns): match an early phrase. `type: 3` is the exact whole line. Gate: `tools/check_wrap.py` | "EXACT WHOLE LINE" |
| A callee that does not exist | Grep the DEFINITION and its `isActive` before you call a helper. A switched-off script does not switch off its callers. Gate: `tools/check_orphans.py` | "nil callee has four shapes" |
| Events | Register the exact event (`gmcp.Room.Info`), not its prefix (`gmcp.Room`) | "prefix event" |
| Silence | Every guard return gives a reason. Zero is an answer; silence is not. A guarded start needs a guarded stop | "Silent gates", "silence is not" |
| Tests | Break back every fix: revert it and see a test fail. Run the real code and the real pattern. All test files share ONE Lua state: restore every global you replace | "Break-backs that pass", "Tests can assert the bug" |
| Evidence about the game | Captured behaviour outranks wiki and AB text. Grep `kb/` and `.claude/classes/` before you ask the maintainer or call a line "uncaptured" | "grep the docs" |
